# AGENTS.md

Instructions for AI agents using or changing this SDK. Humans are welcome too.

## Using the SDK

- **Find an endpoint** in `openapi/manifest.json`. It maps every SendSeven operation (operationId, `METHOD /path`, summary, scopes) to its call, e.g. `$sendseven->contacts()->list()`, with parameter names, types and the return type. `docs/reference/<resource>.md` has the same with examples.
- **Call with named arguments**: `->send(to: '+49…', channelId: $id, text: 'Hi')`. Optional arguments left out are omitted from the request; don't pass `null` to mean "clear".
- **Responses are typed objects.** Read properties (`$message->fromId`); `->raw()` has the original JSON. Enum properties may hold a plain string when SendSeven adds a value: compare with `=== EnumType::Case` and handle the string case.
- **Lists:** methods returning `Page<T>` iterate the page; `->lazy()` walks every page.
- **Webhooks:** always check `Webhook::isVerificationChallenge()` first and answer with `Webhook::challengeResponse()`. Then use `Webhook::constructEvent($rawBody, $headers, $secret)` with the raw body, exactly as received. Match on event classes (`MessageReceived`, `MessageStatusUpdated`, `ChannelEvent`…).
- **Tenancy:** a token is one tenant. Only use `forTenant()` and `tenants()->create()` when `$sendseven->capabilities()->canManageTenants()` or `canCreateTenants()` says so; explain `whyNotCreateTenants()` to the user otherwise.
- **Onboarding channels:** use `connectLinks()->create(ConnectLink::for(...))`. Never try to run Meta's Embedded Signup directly; SendSeven runs it on the connect page. RCS and browser push can't be connected that way (see `docs/guides/channels.md`).
- **Errors** carry a fix in their message. Catch `SendSevenException` for everything; specific classes are listed in the README.
- **Undocumented endpoint?** `$sendseven->request(Method::Post, '/path', body: [...])` keeps authentication, retries and error handling.
- **Tests:** `SendSeven::fake([...])`, then `$fake->assertSent(...)`. Sign webhook bodies with `Webhook::sign()`.

Read `docs/known-quirks.md` before trusting SendSeven's own spec on webhooks, message fields or tenancy.

## Changing the SDK

- **Never edit generated files.** Anything with `@generated by bin/generate` in its header (`src/Resources/*`, `src/Data/*`, most of `src/Enums/*`, `docs/reference/*`, `llms.txt`, `openapi/manifest.json`) is overwritten. To fix one:
  - a wrong or missing spec detail → add a patch in `openapi/patches/*.json`, with an `x-source` saying how it was verified;
  - a naming or typing problem everywhere → change `generator/src`;
  - a helper a resource needs → a hand-written trait `src/Resources/Concerns/{Resource}Helpers.php`, which the generator mixes in.

  Then run `composer generate`.
- **Hand-written code** lives in `src/Http`, `src/Exceptions`, `src/Webhooks`, `src/Onboarding`, `src/Account`, `src/Support`, `src/Testing`, `src/Pagination`, `src/Client.php`, `src/Factory.php` and `src/SendSeven.php`.
- **The bar** (`composer test` must pass):
  - Pint;
  - Rector;
  - PHPStan at max level with strict rules, with no ignores and no baseline;
  - 100% type coverage;
  - Pest, including the contract test that calls all 712 endpoints and the test that every call in the docs exists.
- **Style:**
  - `declare(strict_types=1)`, `final` classes, `readonly` value objects, named constructors;
  - no static state outside `SendSeven`;
  - docblocks only where they add types or meaning.
  - Exception messages say what happened, where, and what to do next.
- **Tests** describe behaviour (`it('retries rate limits with the same idempotency key')`). Use real captured payloads (`tests/Fixtures`) over invented ones.
- **Verify claims about SendSeven** against the live API or docs.sendseven.com, and record the source. If unsure, say so rather than guess.
